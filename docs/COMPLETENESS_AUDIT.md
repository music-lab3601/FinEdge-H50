# 开源交付完整性复核

## 本轮发现与修复

2026年11月10日对已发布的v1.0.0重新匿名克隆，并重新下载三个Release附件。674个Git文件与源码ZIP逐字节一致。随后从原厂压缩包重新核对厂商基底，发现顶层接线、视频通路关闭、约束及工具钩子的集成修改依赖本机已修改缓存，公开仓库缺少相应的重建步骤。

v1.0.1补齐8项集成文件的精确重建配方与命令入口，记录原始文件和目标文件哈希。构建阶段改为只复制清单中的必需文件，防止缓存中的其他文件参与构建。10项旧模块、旧约束、配置和日志保留历史身份并标记为非必需。模型说明中的板测状态也已更新。

## 复现所需外部组件

软件、模型、ROM、自研约束、集成修改和开源第三方组件进入Git。完整板卡构建还需匹配Vivado、Procise、JFM、Icraft、厂商网表/IP输出和启动组件。它们的身份、获取方式及重建步骤分别位于[依赖说明](../external/README.md)、[集成重建](VENDOR_INTEGRATION.md)和[FPGA构建](FPGA_BUILD.md)。真实行情和训练数据依数据提供方条款取得，公开人工合成输入可用于软件与板端功能复现。

后续修改由`finedge.py check checkout`和GitHub Actions持续检查。检查已覆盖本轮遗漏涉及的集成配方、输出哈希绑定和构建清单复制范围。

## 第二轮复核与v1.0.2

第二轮从公开v1.0.1重新克隆并下载附件，682项文件一致。进一步执行训练入口时，确认旧注册式代码依赖迁移前的目录和历史登记，公开目录缺少可独立执行的训练接线。

v1.0.2新增`train prepare/admit/run`，复用现有相对价、归一化、缓存窗口、模型工厂和选取规则，显式接收数据及缓存清单与哈希。原始登记接口按原参数继续转发。训练复现的字段、路径、命令和输出均记录于[训练说明](TRAINING.md)。

本轮实际通过统一CLI完成7个人工连续段的缓存准备、准入和一个CPU训练轮次。30个训练窗、12个开发验证窗，实际执行1次优化器更新，保存并重载33539参数模型，状态哈希一致，权重相对初始化发生变化。完整训练日的复跑需准备配套授权数据和清单。

独立克隆执行702项测试，676通过、26跳过、0失败。四项RTL仿真、CPU网络闭环、ONNX与因果图、定点ROM和原生UDP检查通过。额外核对128项JSON资源与源码映射。分别移除训练入口、顶层RTL、ROM、约束、以太网Tcl、NPU权重、训练说明和许可证后，检查均能拒绝；恢复文件后的完整性检查通过。具体结果见`completeness_validation_v2.json`。
